# バックエンド

## 位置づけ

本書は、CakePHPバックエンドの責務と層の分け方を定義する。ディレクトリの正本は[ディレクトリ構成](102_directory-structure.md)、HTTPインターフェースは[API](303_api.md)、業務処理の候補は[クラス設計](304_class_design.md)を参照する。

## 基本方針

- CakePHPはJSON API、認証・認可、業務処理、永続化、監査および通知連携を担当する。
- Vue.js FRONT固有の表示状態やレイアウトをバックエンドへ持ち込まない。
- Controllerを薄く保ち、複数モデルにまたがる業務処理はApplication Serviceへ分ける。
- 業務ルールはPolicyまたはDomain Serviceへ分け、ControllerやTableへ重複させない。
- データ保存後の正式状態を基準とし、WebSocket通知だけを保存先にしない。

## 責務

| 要素 | 主な責務 |
|---|---|
| API Controller | HTTP入力、認証結果、バリデーション呼出し、レスポンス変換 |
| Application Service | ユースケースの進行、トランザクション、複数モデルの調整 |
| Policy / Domain Service | 権限、状態遷移、得点、スケジュール等の業務ルール |
| Table / Repository | 永続化、検索条件、関連取得 |
| Query Service | 一覧、大型表示、OBS等の読取処理 |
| Common Service | 監査、通知、時刻、言語、外部連携 |

## トランザクションと通知

1. API入力と認可を検証する。
2. トランザクション内で正式状態と監査履歴を保存する。
3. コミット成功後にWebSocketまたは通知キューへ更新を通知する。
4. 通知失敗時も保存済み状態を維持し、再送またはAPI再取得で回復する。

## 認証・認可

- 通常ユーザーと管理者の認証経路を分ける。
- Controllerへ到達したことだけで認可済みとせず、対象イベント、ロール、担当範囲および操作条件を検証する。
- 公開API、通常ユーザーAPI、管理者APIの境界をルートと認可処理の両方で明確にする。
- 詳細は[認証・権限](08_authentication.md)を参照する。

## エラーとログ

- 利用者へ返すエラーとサーバーログへ記録する内部情報を分離する。
- パスワード、トークン、Cookie、接続情報、個人情報をログへ出力しない。
- 業務上の拒否、入力エラー、競合、認証失敗、サーバー障害をAPIで区別できるようにする。
- 監査履歴と技術ログを目的別に分ける。

## 非同期処理

メール、外部通知、再送等は公開や結果確定のトランザクションから分離する。採用するキュー方式とRSプラン上での実行方法は検討中である。

## テスト方針

- 業務ルールは単体テスト、APIはControllerまたは統合テストで確認する。
- 認証、権限、個人情報、結果訂正、オフライン競合には正常系と拒否系のテストを追加する。
- トランザクション失敗、通知失敗、重複要求および競合を確認する。

## 検討中

- Application Service、PolicyおよびRepositoryの具体的な名前空間
- 認可ライブラリとイベント単位権限の実装方式
- メール・通知キューと定期実行方式
- WebSocket配信基盤との接続方式
- APIエラーをドメイン例外へ対応付ける方式
