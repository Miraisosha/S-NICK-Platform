# 100 パブリック

## 位置づけ

引き継ぎ元「パブリックダッシュボード仕様」で合意した、ログイン不要画面の要件を整理する。
公開ページは、イベントを探すところから、申込、当日観戦、結果・配信アーカイブの閲覧までを同じ導線で提供する。

## 導入フェーズ

- フェーズ1は、登録時に自動公開されたイベントの一覧・詳細、ドロー、日程、進行、得点、結果を対象とする。
- フェーズ2は、運営者側の受付・通知・ランキング利用に必要な公開情報を追加する。
- フェーズ3は、選手自身のWeb申込、詳細なイベント状態別表示、ライブ観戦、ランキング公開、過去イベント・配信アーカイブを追加する。
- `SCR-PUB-111`の申込受付中・過去等による高度な分類、`PUB-130`のWeb申込導線、`PUB-150`、`170 公開制御`の予約・限定・終了操作はフェーズ3とする。フェーズ1はカテゴリ閲覧と登録時の自動公開に対応し、トップは公開イベントを開催日時順に表示する。

## 目的

- 観客・選手・関係者が、現在開催中、申込受付中、開催予定、終了済みのイベントをすぐ見つけられるようにする。
- イベントの開催前・開催中・開催後で、必要な情報と操作を適切に切り替える。
- Squash Platformの試合状態を、会場表示、OBS、公開ページで一貫して利用する。

## 110 パブリックダッシュボード

### SCR-PUB-111 トップ

#### ヘッダー

- Squash Platformのサービス名を表示する。日本語画面のフッターには`提供：株式会社未来創社`を小さく表示し、通常のヘッダー、イベント情報および競技情報より前面に出さない。英語画面は`Provided by Miraisosha Co., Ltd.`を初期案とし、正式な英文商号の確認後に確定する。S-NICKの名称、ロゴおよびキャラクターは通常画面へ表示しない。
- 選手ログインを主要導線として表示する。
- 運営者・スタッフログインは選手ログインと区別する。スマートフォンでメニュー内へ格納するかは詳細UI設計で決定する。

#### セクション

次の順にイベントを表示する。

1. 開催中
2. 申込受付中
3. 開催予定
4. 過去のイベント

過去のイベントは直近数件を表示し、アーカイブ一覧への導線を設ける。各セクション内は原則として開催日時順とする。

#### イベントカード

- 代表画像（16:9、中央基準でトリミング）
- イベント名
- 開催日・開催期間
- 会場名・都道府県
- 主催者
- 短い概要
- 状態ラベル（複数表示可）
- 状態に応じた操作ボタン

代表画像がない場合は共通の既定画像を表示する。画像またはイベント名、詳細ボタンから詳細画面へ移動し、カード全体はクリック領域にしない。

#### 状態ラベル

| ラベル | 表示条件 |
|---|---|
| 開催中 | 現在日時が開催期間内 |
| 本日開催 | 開催日が当日 |
| 申込受付中 | 現在日時が申込期間内 |
| 申込締切間近 | 申込締切まで7日以内 |
| まもなく申込開始 | 申込開始前の告知対象期間 |
| 申込終了 | 申込期間終了後 |
| 開催終了 | 開催期間終了後 |
| NEW | 公開開始から原則7日以内。運営者が表示終了を上書き可能 |
| ライブ配信あり | 公開対象の配信が1件以上ある |

申込締切まで3日以内は残日数、24時間以内は残時間を表示し、正確な締切日時も併記する。境界時刻とタイムゾーンは業務ルール詳細化時に確定する。

#### 操作ボタン

| 状態 | 主な導線 |
|---|---|
| 申込受付中 | 詳細、申込 |
| 開催中 | 詳細、日程・進行、ライブ |
| 開催予定 | 詳細 |
| 開催終了 | 結果・アーカイブ |

未ログインで申込を選んだ場合は、選手ログイン後に元のイベント・カテゴリ申込画面へ戻す。

#### 検索・絞り込み

初期対象は次のとおりとする。

- キーワード
- 地域（都道府県等）
- 申込受付中のみ

競技、開催月、カテゴリ等の追加条件は利用状況を見て検討する。

## 120 イベント詳細

### SCR-PUB-121 イベント詳細

同じ公開URLを開催前・開催中・開催後まで維持し、状態に応じて内容を切り替える。

#### ヘッダー・画像

- キャッチコピー、イベント名、サブタイトル、競技、状態ラベル
- 代表画像と画像ギャラリー
- 画像は複数登録可能とし、1件を代表画像に指定する。
- 代表画像が削除された場合は、残存画像の先頭を自動的に代表画像とする。

画像の最大登録数、最大容量、許可形式は検討中。初期候補は10枚、1枚10 MB、JPEG・PNG・WebPとする。

#### 基本情報

- 開催日時・期間
- 申込期間
- 会場（複数可）、住所、地図リンク
- 定員
- 参加資格
- 参加費
- 主催者、主管・協力等の関係団体
- 問い合わせ先
- 詳細説明、注意事項
- 要項・規程・添付資料

規程は版を識別できるようにし、申込時に同意した版を記録する。

## 130 カテゴリ・申込導線

カテゴリの閲覧はフェーズ1、選手自身が申込画面へ進む導線はフェーズ3で導入する。

### SCR-PUB-131 カテゴリ一覧

イベント共通の参加資格に加え、カテゴリごとに次を表示する。

- 状態、カテゴリ名
- 性別、年齢条件、年齢判定基準日
- 参加費、個別参加資格
- 定員、申込期間
- キャンセル待ちの有無
- 備考、公開状態
- 申込ボタン

同一選手による複数カテゴリ申込の可否・組合せ制約を設定できるようにする。申込処理の詳細は [400_Player.md](400_Player.md) を参照する。

## 140 ドロー・日程・進行

### SCR-PUB-141 公開進行画面

- カテゴリ別ドロー。トーナメントはラウンドを横方向へ並べるブラケット、リーグ戦は選手を縦横へ並べる対戦マトリクスで表示する。
- 初期仕様では本選ブラケットだけを表示する。予選から本選への連携と、本選・予選の表示切替は検討保留とする。
- ブラケットの試合カードには、選手、シード、ゲームカウント、各ゲーム得点、試合日時、コート、BYEを表示する。
- リーグ戦のセルには試合予定または結果を表示し、運営者が除外した組合せは「対戦なし」として表示する。マトリクス右端には「対戦なし」を除いた各選手の有効な試合数を自動表示する。勝敗・順位等のその他の集計も右端に表示する候補とする。
- コート別・時間別の試合予定
- スケジュールは横軸をコート、縦軸を時刻とし、開始・終了予定時刻、両選手の公開アイコンと表示名を試合カードで表示する。
- 選手アイコン未登録時はマイカラーと氏名の頭文字による既定アイコン、対戦相手未確定時はプレースホルダーを表示する。
- 開催日が複数ある場合は日付を切り替えて閲覧できるようにする。
- 試合中、終了、遅延、コート変更等の最新状態
- 開催中は、進行中・終了・遅延の件数を簡潔に表示する。
- 公開対象のリアルタイム得点と試合状態を表示する。

確定前情報を公開する範囲と更新頻度は検討中。遅延表示は、試合が未開始のまま現在有効な開始予定時刻から5分以上経過した場合とし、Squash Platformサーバー時刻を基準に判定する。

## 150 ライブ観戦

本機能はフェーズ3で導入する。

### SCR-PUB-151 ライブ一覧・視聴

配信はイベント、開催日、会場、コート、試合の各単位へ関連付けられるようにする。

| 項目 | 内容 |
|---|---|
| 配信サービス | 初期対象はYouTube Live |
| URL・埋込情報 | 視聴URLと埋込に必要な識別情報 |
| 関連先 | 開催日、会場、コート、試合 |
| 時刻 | 配信予定、開始、終了 |
| 状態 | 予定、まもなく開始、配信中、終了、アーカイブ、配信中止 |
| 表示 | サムネイル、公開・非公開 |

配信中はライブ導線を目立たせ、固定されたSquash Platform側URLから対象配信へ案内する。YouTube・OBSの設定と運用は [ライブ配信設計](../04_live-streaming.md) を参照する。

## 160 結果・シリーズ・共有

### SCR-PUB-161 結果・アーカイブ

- 試合単位・カテゴリ単位の結果
- ドローの最終状態
- 写真・配信アーカイブ
- 同一シリーズの過去大会・次回大会
- 関連イベント

結果の確定前表示、訂正履歴、公開終了条件は検討中。

### 共有

- ページ上部と下部に共有導線を配置する。
- 対象はX、LINE、Facebook、メール、URLコピー、QRコード、OS標準共有とする。
- OGP画像は専用画像を優先し、未登録時は代表画像を使用する。推奨候補は1200×630 px。
- ハッシュタグはイベント設定から最大3件を自動設定する候補とする。
- ライブ配信は変動するYouTube URLを直接共有させず、原則として固定のSquash Platform公開URLを共有する。
- 結果共有の可否は運営者が設定できるようにする。

共有クリック数、申込遷移等の集計と流入元計測は将来候補とする。

## 170 公開制御

本機能はフェーズ3で導入する。フェーズ1はイベント登録時に自動公開し、運営者が公開状態を選択する機能を設けない。

イベント、カテゴリ、配信、結果等は次の公開状態を扱う。

- 非公開
- URLを知る利用者のみ閲覧可能
- トップページ掲載
- 公開予約
- 公開終了

検索エンジン向け設定、URL限定公開の厳密なアクセス制御、公開終了後の保持期間は検討中。

## 業務ルール

| ID | ルール |
|---|---|
| BR-PUB-001 | 一覧・詳細には公開対象データだけを表示する。 |
| BR-PUB-002 | 未ログイン申込はログイン後に元の申込対象へ復帰させる。 |
| BR-PUB-003 | 状態ラベルは開催期間・申込期間・手動設定から一貫して算出する。 |
| BR-PUB-004 | 配信や試合状態が変わっても、共有用のSquash Platform公開URLを維持する。 |
| BR-PUB-005 | 終了済みイベントは同じURLで結果・アーカイブへ切り替える。 |

## 非機能要件

- スマートフォンを最優先に、PC・タブレットでも利用できるレスポンシブ表示とする。
- 公開ページは個人情報や運営専用情報を含まない公開用データから生成する。
- 代表画像とギャラリーは表示サイズに応じて最適化し、代替テキストを設定できるようにする。
- ライブ・進行情報が取得できない場合も、イベント基本情報と障害案内を表示できるようにする。
