# 650 通知

- 本仕様でいう「通知」は、スケジュール変更等の業務メッセージとその送信処理を指す。SMTPは初期通知をメールで届けるための送信手段であり、Webプッシュ通知やLINEは将来追加する別の通知手段として区別する。
- 初期通知はSMTPを使用し、接続先、ポート、認証情報および送信元は[認証メール送信](../2000_operator/2104_email_delivery.md)で定義する`SMTP_HOST`、`SMTP_PORT`、`SMTP_USERNAME`、`SMTP_PASSWORD`、`EMAIL_FROM`から取得する。
- SMTP通信は暗号化し、接続設定と認証情報は環境変数またはGit管理外設定で環境ごとに分離する。具体値は設計書、ログ、Gitへ保存しない。
- フェーズ2の試合当日スケジュール変更通知は、選手の確認済みメールアドレスへ受信者ごとに個別送信する。
- スケジュールの下書き編集時には送信せず、変更版の公開を通知イベントとして扱う。
- 同一公開操作内の重複通知をまとめ、同じ選手・同じ試合へ同内容を重複送信しない。
- メール送信はキューで処理し、公開処理と分離する。送信失敗時も公開済みスケジュールは維持し、運営者が失敗を確認・再送できるようにする。
- SMTP接続タイムアウトと再試行はCakePHPの環境別設定として実装時に定義し、SPF、DKIM、DMARCはメールサーバー・DNS側で設定する。
- 通知種別、対象イベント、対象試合、対象利用者、通知手段、宛先、本文、送信者、作成日時、送信日時、送信結果、失敗理由を記録する。
- 将来の通知手段としてWebプッシュ通知とLINE等のメッセージ通知を追加できるよう、メール固有処理と通知内容を分離する。
- 外部通知サービスの認証情報、アクセストークン等は環境変数またはGit管理外の秘密情報として扱う。
- Webプッシュ通知やLINE等は本人の利用開始・連携・解除を前提とし、具体的なサービス、アカウント連携方式、メールとの優先順位、同時送信、通知設定は検討中とする。
