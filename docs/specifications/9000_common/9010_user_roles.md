# 020 利用者・権限

## 利用者

| 利用者 | コード | 主な責務 |
|---|---|---|
| パブリック | `public` | 公開情報、配信、結果の閲覧 |
| 運営者 | `operator` | 大会作成、参加受付、ドロー、進行、連絡 |
| マーカー | `marker` | 担当試合のスコアと試合事象の記録 |
| 選手 | `player` | 申込、決済、プロフィール、自分の試合確認 |
| 管理者 | `admin` | プラットフォーム全体の設定・監査 |

## 権限原則

- 運営者、スタッフ、マーカー、選手等の通常ユーザーは共通アカウントで認証し、役割をイベント単位で付与できるようにする。
- プラットフォーム管理者は通常ユーザーとは別の管理者テーブルと専用ログインで認証し、イベントロールとして管理者権限を付与しない。
- 同じ人物が管理者業務とイベント運営業務の両方を行う場合は、管理者アカウントと通常ユーザーアカウントを別々に登録する。
- 権限は最小権限を基本とする。
- マーカーは担当試合以外を原則編集できない。
- 公開前情報と個人情報は、許可された利用者だけが閲覧できる。
- 重要な変更は、操作者、日時、変更前後の値を履歴に残す。
- メール確認済みユーザーは誰でもイベントを作成でき、作成した個人をイベント所有者とする。
- スタッフも個人の登録済みユーザーとし、ユーザー登録されていない人へスタッフ権限を付与しない。

## 操作権限の表現

詳細仕様では、画面単位に閲覧・登録・更新・削除・実行の可否を定義する。

## イベントスタッフのロール

イベントスタッフには、業務に必要な権限をまとめた固定ロールを1つ以上付与する。フェーズ1では、イベント所有者、大会運営管理者、受付・進行担当、マーカー、スポンサー・表示担当、配信担当、閲覧担当を使用し、カスタムロール作成は将来機能とする。

ロールとは別に、対象イベント、開催日、コート、カテゴリ、時間帯の担当範囲を設定する。権限判定ではロールと担当範囲の両方を満たす必要があり、複数ロールを付与しても各ロールの担当範囲を超えて操作できないようにする。

スタッフ管理、所有者変更、確定済み結果訂正、個人情報閲覧等の重要操作は、対応するロールを持つ利用者だけに許可し、操作者が自分の権限を超えるロールや担当範囲を他者へ付与できないようにする。

確定済み結果は、イベント所有者、大会運営管理者、または対象コート・対象試合を担当するマーカーが訂正できる。担当外のマーカー、受付・進行担当、その他のスタッフおよび選手は訂正できない。プラットフォーム管理者は通常の大会運用として結果を訂正せず、システム障害等の保守対応に限定する。

固定ロール、担当範囲、所有者だけが行える操作、受付・進行担当の禁止操作は要件段階として整理済みとする。主要な業務操作との対応は[権限マトリクス](9402_authorization_matrix.md)で管理し、画面・APIおよび入力項目の確定に合わせて詳細化する。
