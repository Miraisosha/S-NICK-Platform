# 権限マトリクス

## 位置づけ

本書は、Squash Platformの業務操作とイベントロール・管理者区分の対応を管理する権限設計の正本である。認証方式は[認証・権限](9401_authentication_authorization.md)、利用者と固定ロールは[利用者・権限](9010_user_roles.md)、個別機能の業務条件は各機能仕様を参照する。

- 初版確認日：2026年8月26日
- 対象：要件が確認できる主要操作
- 更新方針：画面、APIおよび入力項目の確定に合わせて操作を追加・細分化する

## 記号

| 記号 | 意味 |
|---|---|
| ○ | ロールとして許可する。所属状態やイベント状態等の共通条件は別途確認する |
| △ | 担当範囲、対象試合、操作権、状態、理由入力等の追加条件を満たす場合だけ許可する |
| × | ロールとして許可しない |
| 検討中 | 仕様上の判断が残っているため確定しない |
| ― | その認証区分の対象外 |

マトリクスの許可はAPIで判定する。画面にボタンが表示されること、URLを知っていること、QRコードを読み取れることだけを許可の根拠にしない。

## 追加条件

| 条件 | 判定内容 |
|---|---|
| 有効な所属 | `event_staff`が招待中・解除済み等ではなく、有効な状態であること |
| 担当範囲 | ロールごとに設定された開催日、コート、カテゴリ、時間帯のすべてを満たすこと |
| 複数ロール | 各ロールの許可を、そのロール自身の担当範囲内で合成する。他ロールの広い範囲を流用しないこと |
| イベント状態 | プラットフォーム停止、終了、公開済み等の状態により操作が禁止されていないこと |
| 試合状態 | 開始前、進行中、終了済み等、その操作を受け付ける状態であること |
| 操作権 | 得点入力や端末引継ぎでは、担当範囲に加えて現在の操作権と世代番号を確認すること |
| 個人情報 | 業務に必要な最小項目だけを表示し、同じロールでも操作目的に不要な項目は返さないこと |
| 重要操作 | 所有者変更、権限変更、結果訂正、強制引継ぎ、競合解決等では理由・確認・監査履歴を必要とすること |

`△`の具体的な条件は、対象機能の仕様書とAPI設計で確定する。条件が未実装の場合は広く許可せず、原則として拒否する。

イベント作成は、確認済みメールアドレスを持つ有効な通常ユーザーに許可し、作成者をイベント所有者として登録する。選手は通常ユーザーと共通アカウントであるため、選手であることを理由にイベント作成を禁止しない。

## プラットフォーム管理者

プラットフォーム管理者はイベントロールを継承せず、通常の大会運営には参加しない。同じ人物がイベントを運営する場合は、別の通常ユーザーアカウントを使用する。

| 業務操作 | 管理者 `admin` | スーパー管理者 `super_admin` |
|---|:---:|:---:|
| 通常ユーザー・関係イベント・セキュリティ状態の閲覧 | ○ | ○ |
| 通常ユーザーの利用停止・再開・全端末ログアウト | △ | △ |
| 施設・コート共通マスターの管理 | ○ | ○ |
| イベント横断の状態確認 | ○ | ○ |
| システム障害等に伴うイベント保守操作 | △ | △ |
| 通常のイベント編集・得点入力・結果訂正 | × | × |
| システム監査ログの閲覧 | ○ | ○ |
| 管理者アカウントの作成・停止・再開 | × | ○ |
| 管理者区分の変更 | × | ○ |
| 重大なシステム設定 | × | ○ |

利用停止、イベント保守操作および重大な設定変更は、理由入力、影響範囲の確認および監査履歴を必須とする。最後の有効なスーパー管理者を停止または降格できないようにする。

## 実装への対応

権限判定は、次の順序を基本とする。

1. 認証区分を確認する。
2. 対象データが所属するイベントを確定する。
3. 有効なイベント所属と固定ロールを確認する。
4. ロールごとの担当範囲を確認する。
5. イベント・試合・問い合わせ等の現在状態と追加条件を確認する。
6. 許可された場合だけApplication Serviceを実行する。
7. 重要操作は変更結果と操作者を監査履歴へ保存する。

CakePHP Authorizationを採用する場合は、少なくとも`EventPolicy`、`CategoryPolicy`、`ParticipantPolicy`、`SchedulePolicy`、`MatchPolicy`、`InquiryPolicy`、`DisplayPolicy`および`StreamingPolicy`へ本書の操作を対応付ける。一覧取得では、取得後に非表示化するだけでなく、検索条件へ認可範囲を適用する。

## 検討中

- 大会運営管理者にイベント・カテゴリの削除を許可するか
- 閲覧担当が参照できる参加選手情報の範囲
- 問い合わせ担当を独立した固定ロールとして追加するか、既存ロールの権限に含めるか
- イベント監査履歴を各スタッフロールへどこまで公開するか
- 受付・進行担当および担当マーカーが強制引継ぎ・競合解決できる具体的な条件
- 個人情報を項目単位で制限するPolicyとレスポンス変換の分担
- 画面・API確定後の操作コード、API、Policyメソッドおよびテストケースとの対応表
