# 500 管理者

> Document Status: Draft
>
> Requirements Version: 1.0

## 目的

個別イベントの運営を越えて、Squash Platform全体を安全に管理する。管理者は通常のイベント運営業務を行わず、利用者、共通マスター、監査、障害および保守を管理する。

## 501 管理者アカウントと認証

### アカウント分離

- 管理者は、運営者、イベント所有者、スタッフ、マーカー、選手等の通常ユーザーとは完全に別の管理者テーブルで管理する。
- 通常ユーザーは`users`、管理者は`admins`を認証元とし、管理者権限を通常ユーザーのイベントロールとして付与しない。
- 同じ人物が管理者業務とイベント運営業務の両方を行う場合は、管理者アカウントと通常ユーザーアカウントを別々に登録する。
- 管理者アカウントはイベント所有者、イベントスタッフ、マーカーまたは選手としてイベントへ関連付けない。

### 管理者専用ログイン

- 管理者は`/admin/login`からログインし、通常ユーザーのログイン画面を使用しない。
- 管理者画面、認証ガード、ログインセッション、自動ログイン、パスワード再設定およびCookieは通常ユーザーと分離する。
- 管理者のパスワードもArgon2idでハッシュ化し、平文または復号可能な形式で保存しない。
- 管理者用メールアドレスには、通常のイベント運営で使用するものとは異なる業務用アドレスの利用を推奨する。
- 二要素認証の必須化方式と導入フェーズは、管理者セキュリティの詳細設計で確定する。

### 管理者テーブルの主要項目

| 項目 | 内容 |
|---|---|
| `id` | 内部管理者ID |
| `admin_code` | 画面・問い合わせ・監査で使用する変更不可の管理者番号 |
| `name` | 管理者表示名 |
| `email` | 管理者ログイン用メールアドレス |
| `password_hash` | パスワードハッシュ |
| `role` | `admin`または`super_admin` |
| `status` | 有効、停止等の管理者アカウント状態 |
| `mfa_enabled` | 二要素認証設定状態 |
| `last_login_at` | 最終ログイン日時 |
| `created_at` | 登録日時 |
| `updated_at` | 更新日時 |

### 管理者区分

| 区分 | 権限 |
|---|---|
| 管理者 | 通常ユーザー、施設・コート、イベント、監査およびシステム状態の管理 |
| スーパー管理者 | 管理者アカウントの作成・停止・再開、管理者区分の変更および重大なシステム設定 |

管理者が別の管理者を自由に作成できないようにし、`admins`の作成、停止、再開および`admin`／`super_admin`の変更はスーパー管理者だけに許可する。

## 500 管理者ダッシュボード

### SCR-ADM-5001 管理者ダッシュボード

フェーズ1は各管理機能への入口と、対応が必要な異常を確認するための簡易画面とする。詳細な分析、グラフ、ウィジェット編集等は作り込まず、フェーズ3で実際の運用要望をもとに再設計する。

表示内容は次のとおりとする。

- 通常ユーザー総数と利用停止数
- 開催中イベント数と開催予定イベント数
- 未解決の同期エラーおよびシステムエラー
- 直近の管理者操作
- 利用者管理、施設・コート管理、イベント横断確認、監査ログ、システム設定へのメニュー

ダッシュボードからデータを直接編集せず、各管理画面へ移動して操作する。異常がない場合はメニューを中心に表示し、対応が必要な問題がある場合だけ警告を強調する。

## 510 利用者・運営者管理

本機能は`users`テーブルの通常ユーザーだけを対象とし、`admins`テーブルの管理者を表示・管理しない。

### SCR-ADM-5101 アカウント一覧

#### 表示項目

| 項目 | 内容 | ソート |
|---|---|:---:|
| アイコン | 登録済みの運営者アイコン。未登録・取得失敗時は表示名の頭文字による既定アイコン | ― |
| アカウント番号 | メールアドレスとは別に自動生成する変更不可の番号。例：`SNK-000001` | ○ |
| 表示名 | ユーザーテーブルの表示名。重複を許可する | ○ |
| 利用状況 | イベント所有者、イベントスタッフ、マーカー等の複数表示 | ○ |
| 登録日 | アカウント登録日時 | ○ |
| 所有イベント数 | 所有者として登録されている対象イベント数 | ○ |
| 参加イベント数 | スタッフまたはマーカーとして関連する対象イベント数 | ○ |
| 最終ログイン | 最後に成功したログイン日時 | ○ |
| ステータス | 未確認、有効、停止、退会 | ○ |

アカウント番号はログインIDとして使用しない。ログインには確認済みメールアドレスを使用し、メールアドレスを変更しても内部ユーザーID、アカウント番号、所有イベント、スタッフ関係および操作履歴を維持する。

利用状況は固定のアカウント区分ではなく、イベントとの関係から算出する。一人の通常ユーザーがイベントを作成してイベント所有者になり、別イベントへ招待されてマーカーになることを許可する。どのイベントとも関係がない場合は「一般利用者」と表示する。

イベント数には開催予定、開催中、終了および中止イベントを含める。フリーマッチと削除済みイベントは含めない。所有イベント数と参加イベント数を分けて表示する。

列ヘッダーのクリックで昇順・降順を切り替え、現在の並び順を矢印等で表示する。初期表示は登録日の新しい順とし、同じ値の場合はアカウント番号を第二ソート条件に使用する。初期表示件数は50件とし、サーバー側ページングを使用する。

#### 検索

- 表示名・氏名：部分一致
- アカウント番号：完全一致または前方一致
- 利用状況：イベント所有者、イベントスタッフ、マーカー等の複数選択
- ステータス：未確認、有効、停止、退会の複数選択
- 登録日：開始日・終了日の範囲指定

検索条件は組み合わせて使用できるようにする。メールアドレスは個人情報のため一覧へ常時表示せず、許可された管理者が詳細画面で確認する。

ステータスは色だけでなく、文字とアイコンを併記する。一覧上では利用停止・再開を直接実行せず、行または明示的な詳細リンクからアカウント詳細画面へ遷移する。

### SCR-ADM-5102 アカウント詳細

#### ヘッダー

- 運営者アイコン
- 表示名
- アカウント番号
- ステータス
- イベント所有者、スタッフ、マーカー等の利用状況
- 登録日時
- 最終ログイン日時

#### 基本情報

| 項目 | 内容 |
|---|---|
| アカウント番号 | 変更不可 |
| 表示名 | 重複可能 |
| 氏名 | 登録されている場合に表示 |
| メールアドレス | ログイン用。管理者だけが詳細画面で閲覧 |
| メール確認状態 | 未確認または確認済み |
| 登録・更新日時 | アカウントの作成・更新日時 |
| 最終ログイン | 成功した最終ログイン日時 |
| ステータス | 未確認、有効、停止、退会 |

管理者は原則として通常ユーザーの表示名、氏名、メールアドレス等のプロフィールを編集せず、閲覧のみとする。プロフィール変更は本人の機能から行う。

#### 関係イベント

| 項目 | 内容 |
|---|---|
| イベント名 | イベント横断確認へのリンク |
| 関係 | 所有者、スタッフ、マーカー |
| スタッフロール | 大会運営管理者、受付・進行担当等 |
| 開催期間 | 開始日から終了日 |
| イベント状態 | 開催予定、開催中、終了、中止、プラットフォーム停止 |
| アクセス状態 | 有効または停止 |

#### ログイン・セキュリティ

- メール確認状態
- 最終ログイン日時
- 直近のログイン失敗日時と連続失敗回数
- 有効なセッション数
- 自動ログインの有無
- 最終パスワード変更日時

管理者は全端末ログアウト、確認メール再送、利用停止および利用再開を実行できる。管理者は通常ユーザーのパスワードを閲覧または任意設定せず、本人のパスワード再設定手続きを使用する。

#### 利用停止・再開履歴

停止・再開の種別、理由、実行管理者、実行日時、停止期限、影響イベントを時系列で表示する。過去の履歴は編集・削除できない。

#### アカウント監査ログ

アカウント登録、メール確認、ログイン成功・失敗、プロフィール・メール変更、イベント作成、スタッフ招待・解除、イベントロール変更、利用停止・再開、全端末ログアウトおよび退会を表示する。フェーズ1では直近100件を表示し、詳細検索は`540 システム設定・監査`で行う。

### SCR-ADM-511 利用停止・再開

- 管理者はイベント開催中であっても通常ユーザーを利用停止できる。
- 停止理由を必須とし、停止日時、実行管理者、停止期限または無期限、再開日時および再開管理者を記録する。
- 利用停止時は対象ユーザーの全端末セッションと自動ログインを無効化し、新しいログインを拒否する。
- 選手申込、試合結果、イベント・スタッフ関係および操作履歴は削除せず保持する。
- 退会は本人が行う機能、利用停止は管理者が行う措置として区別する。

停止対象がイベント所有者の場合は、停止前に所有イベント、開催中・開催予定イベント、所属スタッフおよび進行中試合への影響を表示する。停止確定後は所有イベントを「プラットフォーム停止」とし、当該イベントに関連するスタッフ、マーカーおよび表示・配信担当を含む全通常ユーザーのアクセスを停止する。

停止対象がイベント所有者ではなく、イベントスタッフまたはマーカーだけの場合は、対象本人のアクセスだけを停止し、イベント全体は停止しない。

停止中イベントの利用者向け表示は、事情を断定せず次の文言を基本とする。

> このイベントは現在利用を停止しています。詳しくは大会運営者へお問い合わせください。

管理者画面では停止理由、停止管理者、停止日時および影響範囲を確認できるようにする。停止操作と対象イベントの状態変更を監査ログへ記録する。

通常ユーザーの再開とイベントの再開は分離する。ユーザーを再開しても、プラットフォーム停止となった所有イベントを自動再開しない。管理者がイベントごとに影響を確認して再開し、再開したイベントのスタッフアクセスを復旧する。

## 520 マスター管理

- 会場・コート等の共通マスターの登録・編集・削除
- システム共通の選択肢・表示設定
- スカッシュ協会ランキングExcelの取込・版管理

### SCR-ADM-522 施設・コート管理

- 施設と施設内の個別コートは管理者だけが登録・編集・削除できる。
- 施設名、住所、都道府県、緯度・経度、地図リンク、ホームページURL、連絡先、コート数、個別コート名・識別子、設備、備考を管理する。
- 運営者はイベント作成・編集時に登録済み施設と個別コートを選択するだけとし、共通マスターを変更できない。
- イベントまたは試合で参照中の施設・コートは、影響を確認せず削除できない。

### SCR-ADM-521 スカッシュ協会ランキング取込

本機能はフェーズ2で導入する。フェーズ1ではランキング取込・自動照合・シード利用を行わない。

- 管理者がスカッシュ協会のランキング表Excelをアップロードする。
- ランキング種別、対象年月・基準日、性別・区分、出典、取込日時、取込担当者を記録する。
- Excelの列、行数、解析結果、エラー行をプレビューし、管理者が確定するまでランキングマスターへ反映しない。
- 氏名、順位、ポイント、所属、協会側識別情報等、Excelに含まれる利用可能な項目を取り込む。
- 同じランキング種別・基準日の再取込では、既存版を直接上書きせず新しい版として保持する。
- 元Excelとファイル識別情報を保持し、どの資料から登録したか追跡できるようにする。
- 取込確定後、運営者の選手管理・ドロー作成から参照できる状態にする。
- Excel形式が想定と異なる場合は処理を中止し、解析できない列・行を表示する。

協会Excelの正式な列構成、ランキング種別、過去版の保存期間、誤取込時の取消手順は検討中とする。

## 530 イベント横断管理

- イベント、ドロー、試合、スポンサー、スタッフおよび選手を横断確認する。
- 通常操作は読み取り専用を基本とする。
- 通常の確定済み結果訂正は行わず、システム障害、データ破損等の保守対応だけを監査履歴付きで行う。
- 所有者停止に伴うプラットフォーム停止イベントの影響確認および再開を行う。

## 540 システム設定・監査

- 権限、外部連携および保守設定
- 通常ユーザー・管理者・システムを区別した操作履歴
- エラー、同期失敗、通知・連携状況の確認
- 対象、期間、操作種別、実行者による監査ログ検索

監査ログの操作主体は`user`、`admin`、`system`を区別し、管理者操作には通常ユーザーIDではなく管理者IDを記録する。

## 550 管理者アカウント管理

本機能はスーパー管理者だけが使用する。

- 管理者一覧・詳細
- 管理者アカウントの作成、停止、再開
- `admin`と`super_admin`の変更
- 管理者の全端末ログアウト
- 管理者ログインおよび重要操作の監査

管理者アカウントを物理削除せず、停止状態と監査履歴を保持する。スーパー管理者が自分自身を最後の有効なスーパー管理者ではない状態に変更することを禁止する。

## 要件ID

| ID | 要件 |
|---|---|
| ADM-001 | 管理者を通常ユーザーとは別の`admins`テーブルで管理する |

| ADM-003 | フェーズ1に簡易管理者ダッシュボードを提供する |
| ADM-004 | 通常ユーザーを検索・ソート・ページングして一覧表示する |
| ADM-005 | 通常ユーザーのアカウント番号、表示名、利用状況、イベント数、ログインおよび状態を確認する |
| ADM-006 | 通常ユーザーの詳細、関係イベント、セキュリティ状態および監査ログを確認する |
| ADM-007 | 管理者がイベント開催中でも通常ユーザーを理由付きで利用停止できる |
| ADM-008 | イベント所有者の利用停止時に所有イベントと関係スタッフのアクセスを停止する |
| ADM-009 | 通常ユーザーの再開とプラットフォーム停止イベントの再開を分離する |
| ADM-010 | 施設・コート共通マスターを管理する |
| ADM-011 | 全イベントを横断確認し、通常の大会運用と保守操作を分離する |
| ADM-012 | 通常ユーザー、管理者、システムを区別して重要操作を監査する |
| ADM-013 | スーパー管理者だけが管理者アカウントと管理者区分を管理できる |

## 検討中

- 管理者二要素認証の必須化方式と導入フェーズ
- 管理者アカウントのパスワード・セッション有効期間
- プラットフォーム停止イベントに進行中のオフライン試合がある場合の停止・同期手順
- フェーズ3における管理者ダッシュボードの集計・分析・ウィジェット要件
- フェーズ1で除外する管理者一覧の一括操作、CSV出力、保存済み検索等の最終範囲
- ランキングExcelの正式な列構成、保存期間および誤取込取消手順
