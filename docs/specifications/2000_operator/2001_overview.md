# 運営者概要

## 位置づけ

運営者が共通アカウントを登録し、イベントの準備、募集、ドロー、当日進行、会場表示、ライブ配信、結果確定までを管理するための要件を定義する。

大会・開催単位を表す画面表示名と業務用語は「イベント」に統一する。「タイトル」はYouTubeの配信タイトルやHTMLタイトル等、一般的な名称欄を指す場合にだけ使用する。

## 目的

- 初めて利用する人が少ない入力でアカウントを作成できるようにする。
- 運営者が最近利用したイベントや対応が必要な試合へすぐ移動できるようにする。
- イベント情報、カテゴリ、エントリー、選手、ドロー、試合進行を一貫して管理する。
- スポンサー、スタッフ、コート、マーカー、会場表示、ライブ配信をイベントへ関連付ける。
- 個人情報と重要操作を権限・履歴により安全に管理する。

## 利用端末・レスポンシブ方針

- 運営者画面はPCブラウザでの利用を主用途とし、広い画面では一覧、検索条件、詳細情報および操作を効率よく確認できるレイアウトとする。
- 大会当日の緊急対応、移動中の確認およびPC故障時の代替を考慮し、タブレットとスマートフォンの一般的な最新ブラウザからも利用できるレスポンシブ表示とする。
- タブレット・スマートフォンでも、フェーズ1の主要な運営操作を画面幅だけを理由に非表示または閲覧専用へ変更しない。PCと同じ権限判定、確認手順および監査記録を使用する。
- 狭い画面では、複数列を縦積みにする、表をカードまたは項目別表示へ切り替える、検索条件を開閉式にする、主要操作を画面下部へ固定する等の方法で操作性を維持する。
- ドロー、リーグ表、スケジュール等、構造上横幅が必要な画面は、ラウンド・表示範囲の切替、代替一覧および必要最小限の横スクロールを組み合わせる。情報全体を読めない大きさまで一律縮小しない。
- ドラッグ＆ドロップだけに依存せず、順位番号、移動先選択、上下ボタン等、タッチ端末でも実行できる代替操作を提供する。
- スマートフォンでは主要ボタンと入力欄のタップ領域を確保し、画面端へ小さな操作アイコンを密集させない。
- 試合一覧から試合詳細へ移動する場合は、行またはカード全体をクリック・タップ領域とし、行内へ「詳細」ボタンを設置しない。マウスのホバー、キーボードフォーカスおよびタップ時の反応を明示し、行・カードをリンクとして操作できるようにする。
- 対戦選手の表示は`Player A vs Player B`形式に統一し、`対`は使用しない。実際の選手名でも`佐藤 花子 vs 鈴木 美咲`のように表示する。
- PC、タブレット、スマートフォンで別の業務状態を持たず、同じサーバー上の最新状態を表示する。

各画面のPC・タブレット・スマートフォン配置は画面レイアウト設計で定める。共通の文字、ボタン、余白および配色は[フロントエンド](../../architecture/301_frontend.md)を参照する。

代表的なレスポンシブ構成は、[運営者画面の初期デザイン案](../../architecture/301_frontend.md#運営者画面の初期デザイン案)を参照する。

## 機能構成

| コード | 機能 | 主な画面 |
|---|---|---|
| OPR-210 | 認証・アカウント | ユーザー登録、メール確認、ログイン、パスワード再設定 |
| OPR-220 | ユーザー設定 | プロフィール、メールアドレス変更、パスワード変更 |
| OPR-230 | メニュー・ダッシュボード（フェーズ2） | 内容は他機能の確定後に再設計 |
| OPR-240 | イベント管理（フェーズ1～3） | フェーズ1は手動運用、フェーズ2は自動化、フェーズ3は申込・決済・状態拡張 |
| OPR-250 | スポンサー・スタッフ管理 | スポンサー素材、スタッフ招待、担当・権限 |
| OPR-260 | コート管理 | 施設、個別コート、所在地、利用情報 |
| OPR-270 | マーカー・大型表示 | マーカー割当、進行・得点連携、会場表示 |
| OPR-280 | ライブ配信管理（フェーズ3） | YouTube配信、OBS、公開URL、配信状態 |
