# イベント問い合わせ

## 位置づけ

イベントごとの問い合わせ受付と対応履歴を管理する。送信側の画面は[1311 イベント問い合わせ](../1000_public/1311_event_inquiry.md)、本書は問い合わせ全体の業務ルールを正本とする。

## 決定済み

- 問い合わせは必ず一つのイベントに所属する。
- 運営者は権限を持つイベントの問い合わせだけを閲覧・更新できる。
- イベントをまたいだ問い合わせの閲覧と返信を禁止する。
- 問い合わせ本文と返信をメッセージ履歴として保持し、上書きしない。
- 送信者、送信日時、対応者、返信日時および状態変更を記録する。
- システム全体への問い合わせはイベント問い合わせと分離する。

## データ関係

```text
イベント
└─ 問い合わせ
   ├─ 問い合わせ送信者
   ├─ 問い合わせ状態
   └─ メッセージ履歴
      ├─ 質問
      └─ 返信
```

## 状態候補

```text
未対応 → 対応中 → 回答済み → 完了
```

再開、重複、対応不要等の状態を追加するかは検討中とする。

## 権限

イベント所有者、大会運営管理者、または問い合わせ対応を許可されたスタッフが管理する。既存の固定ロールへ含めるか、問い合わせ担当ロールを追加するかは検討中とする。

## 通知

受付時と返信時にメール等で通知することを候補とする。通知失敗時も問い合わせ・返信の保存済み状態を維持する。

## 検討中

- 導入フェーズ
- 未ログイン送信の可否
- 問い合わせ担当ロール
- 状態、優先度、カテゴリ、担当割当
- 添付ファイル
- 返信通知、受付番号および利用者側の履歴画面
- 保存期間と個人情報の閲覧範囲
