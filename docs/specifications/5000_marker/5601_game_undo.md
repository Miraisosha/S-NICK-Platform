# ゲーム管理・UNDO

## 360 ゲーム管理・UNDO

### ゲームスコア

- フェーズ1は最大5ゲーム分を表示する。将来、規定ゲーム数が5を超える場合も同じゲーム表示部品を繰り返し、スクロール等で全ゲームを確認できる構造とする。
- 終了ゲームは最終ポイントを表示する。
- 現在ゲームは枠、ラベル等で明確に強調する。
- 未開始ゲームは`- / -`で表示する。
- 過去ゲームをタップすると、ゲーム結果と読み取り専用マーカーボードをダイアログ表示する。
- 通常の試合進行中は過去ゲームを直接編集・UNDOできない。試合終了後の訂正では、操作履歴全体をリセットして最初から再入力する。

### ゲーム・試合終了

- カテゴリのゲーム終了点が`1`～`100`の場合は、その点数以上かつ必要点差`1`または`2`を満たした時点でゲーム決着を自動判定する。
- ゲーム終了点が`0`の場合は手動終了方式とし、ゲームの自動終了判定を行わない。マーカーが各ゲームの終了を手動確定する。
- ゲーム終了点が`0`かつ最大ゲーム数が`1`の場合は、手動終了時点の左右の得点を合計得点として比較し、高い選手を勝者とする。同点の場合は延長や決勝点を追加せず「勝敗なし」とする。
- ゲーム終了点が`0`かつ最大ゲーム数が`3`または`5`の場合は、各ゲームをマーカーが手動終了し、ゲーム獲得数で勝敗を決定する。3ゲームマッチは2ゲーム先取、5ゲームマッチは3ゲーム先取とし、過半数へ到達した時点で残りゲームを実施せず試合を終了できる。
- 1ゲームマッチの試合終了確認には左右の得点と判定結果（左勝利／右勝利／勝敗なし）、3・5ゲームマッチでは各ゲーム得点、ゲーム獲得数および勝者を表示する。
- 1ゲームマッチの「勝敗なし」では勝者と敗者を設定せず、試合を`finished`として確定する。その後のグループ戦の試合進行は妨げず、左右の得点を将来のグループ順位・進出判定で使用できるように保存する。
- 棄権、Conduct Match、試合授与等が確定した場合は、最大ゲーム数や現在のゲーム獲得数にかかわらず、その終了結果を優先する。Injury Timeの開始または時間終了だけでは勝敗を決定せず、審判・マーカーが試合再開、棄権、試合授与等を選択する。
- 試合の必要ゲーム数に到達した場合は、即時確定せず試合終了確認を表示する。
- 確定時に勝者、終了時刻、ゲーム結果、終了種別を保存する。
- キャンセル時は現在ゲームへ戻り、必要に応じてUNDOできる。

#### 将来のグループ戦を考慮した試合構造

- フェーズ1は最大ゲーム数`1`、`3`、`5`の先取制を提供するが、内部データではゲーム数をこの3種類だけに固定しない。
- 試合進行方式として、過半数先取で終了する「先取制」と、設定した全ゲームを行う「規定ゲーム数制」を区別できる構造とする。規定ゲーム数制の画面提供時期と設定可能なゲーム数の上限は検討中とする。
- 規定ゲーム数制では、将来`2`、`4`等の偶数ゲームや5ゲームを超える大会方式を設定できるようにし、途中で一方が過半数へ到達しても自動終了しない。
- 全規定ゲーム終了後、ゲーム獲得数または合計得点が同じ場合も、勝者なしの引き分けとして`finished`へ遷移できるようにする。具体的な勝敗判定方式はカテゴリ設定で選択できる構造とする。
- 勝者・敗者は必須項目にせず、結果種別として左勝利、右勝利、引き分け、棄権、試合授与、中止等を区別する。
- 各ゲームの左右得点を保存し、試合単位およびグループ集計で、試合数、勝、敗、引き分け、得ゲーム、失ゲーム、ゲーム得失差、得点、失点、得失点差を再計算できるようにする。
- グループ順位における順位点、ゲーム得失差、得失点差、直接対決等の適用順は大会ごとに異なるため検討中とし、集計元データは順位方式と分離して保存する。

### UNDO

画面表示は「戻る」または「取消」、内部イベント名は`UNDO`とする。ブラウザの戻る操作とは明確に区別する。

- 直前の1イベントだけを確認なしで取り消す。
- 得点だけでなく、サーブ権、サービスボックス、ボード行、ゲーム数、試合状態を操作前へ完全復元する。
- 判定イベントでは、判定行と関連する得点・サーブ状態を一括して取り消す。
- 取消対象がない場合はボタンを無効化する。
- 取消対象の概要をボタン付近に表示する。
- 操作履歴は読み取り専用で参照できるが、途中のイベントだけを選んで取り消すことはできない。
- 試合終了後も、終了操作のUNDOまたは操作履歴全体のリセット・再入力を選択できる。途中のイベントだけを選択して削除・変更することはできない。
